# EasyClaw

소형 Linux 보드에 PicoClaw를 사전 구성하여, 전원만 꽂으면 바로 동작하는 AI 비서 완제품. 기술을 몰라도 가상 직원이 생긴다.

제품은 하나다. 손바닥 크기의 SBC(Single Board Computer)에 Docker 컨테이너로 격리된 [PicoClaw](https://github.com/sipeed/picoclaw)가 탑재되어 출하된다. 기본적으로 클라우드 API(OpenRouter)를 두뇌로 사용하며, 보안이 필요한 경우 사용자의 자기 컴퓨터에서 로컬 LLM을 돌려 그것을 두뇌로 쓸 수 있다.

## 왜 만드는가

AI 에이전트 오픈소스 생태계는 폭발적으로 성장하고 있다.

| 프로젝트 | 언어 | 특징 | GitHub Stars |
|----------|------|------|-------------|
| [OpenClaw](https://github.com/openclaw/openclaw) | TypeScript | 원조. 4개 도구, 자율 에이전트, 5,700+ 스킬 | 100,000+ |
| [PicoClaw](https://github.com/sipeed/picoclaw) | Go | 초경량. <10MB RAM, 13+ LLM 프로바이더, 10+ 채널 | 20,000+ |
| [NanoClaw](https://github.com/qwibitai/nanoclaw) | TypeScript | 컨테이너 격리, Agent Swarm, ~500줄 핵심 로직 | ~10,000 |
| [Nanobot](https://github.com/HKUDS/nanobot) | Python | MCP 기반, 4,000줄, 8+ 채팅 플랫폼 | 다수 |

그런데 이 도구들의 실제 사용자는 개발자, 해커, 얼리어답터뿐이다. 터미널을 열고, Git을 쓰고, API 키를 환경 변수에 넣을 줄 아는 사람들.

**진짜 파급력은 그 반대편에 있다.** 한국의 소상공인, 1인 창업가, 프리랜서 — 혼자서 회계, 고객 응대, 마케팅, 재고 관리, 세금 준비를 전부 하는 사람들. 직원을 고용할 여력은 없고, AI가 도와줄 수 있다는 건 알지만 어디서 시작해야 할지 모른다.

현재의 장벽:

- **설치** — Git clone, 의존성 설치, 환경 변수 설정, 포트 포워딩
- **구성** — config.json 편집, LLM 프로바이더 선택, 채널 연동, 스킬 설치
- **유지보수** — 업데이트, 모델 교체, 오류 대응, 보안 패치
- **인프라** — 24시간 구동할 서버, 네트워크 설정, 프로세스 관리

EasyClaw는 이 모든 과정을 사전에 완료한 채 하드웨어에 담아 배송한다. 사용자에게 남는 것은 전원 연결과 API 키 입력뿐이다.

## 왜 PicoClaw인가

| 기준 | PicoClaw | 선정 이유 |
|------|----------|-----------|
| 언어 | Go | 단일 정적 바이너리. 크로스 컴파일로 ARM/RISC-V 어디든 배포 가능 |
| 메모리 | <10MB | SBC의 제한된 리소스에서 여유롭게 구동 |
| 구동 시간 | <1초 (0.6GHz 싱글코어) | 전원 ON 즉시 동작 |
| LLM 프로바이더 | 13+ | OpenRouter, Anthropic, OpenAI, Gemini, DeepSeek, Groq, vLLM 등 — 클라우드든 로컬이든 모델 프리픽스로 자동 라우팅 |
| 채널 | 10+ | 텔레그램, 디스코드, QQ, 딩톡, LINE, WeCom 등 |
| 도구 | 파일, 웹, 셸, 크론, 에이전트 스폰 | 풀스택 에이전트 기능 |
| 하드웨어 통합 | SPI/I2C 지원 | SBC의 GPIO 활용 가능 (IoT 확장) |
| 운영 모드 | Gateway (24/7 상시 대기) | 서버리스 데몬으로 완제품에 적합 |

PicoClaw는 $10짜리 RISC-V 보드에서 동작하도록 설계되었다. EasyClaw가 추구하는 "저렴한 완제품 하드웨어"에 가장 정확히 들어맞는다.

## 두 가지 두뇌

EasyClaw는 하나의 기기에서 두 가지 두뇌를 선택할 수 있다. 소프트웨어와 하드웨어는 동일하다. 차이는 LLM 추론이 어디서 일어나느냐뿐이다.

### 클라우드 모드 (기본)

> OpenRouter API 키만 넣으면 바로 동작한다.

```
[사용자] ←→ [카카오톡/텔레그램/전용앱]
                    │
              [EasyClaw SBC]
              Docker → PicoClaw
                    │
                    ├── OpenRouter API → 클라우드 LLM 추론
                    ├── Twilio → SMS 발신 / SIP Trunk (전화)
                    ├── SendGrid → 이메일 발신
                    └── LiveKit SIP → 음성 파이프라인 (VAD→STT→LLM→TTS)
```

- 가장 간단한 설정. 전원 + Wi-Fi + API 키 = 끝.
- 최신 모델 자동 적용 (OpenRouter가 모델 관리)
- API 사용량에 따른 종량 비용 발생

### 로컬 모드 (선택)

> 보안이 중요한 경우, 자기 컴퓨터에서 로컬 LLM을 돌리고 EasyClaw가 그것을 두뇌로 사용한다.

```
[사용자] ←→ [카카오톡/텔레그램/전용앱]
                    │
              [EasyClaw SBC]                    [사용자의 컴퓨터]
              Docker → PicoClaw  ──(LAN)──→  EasyClaw Companion
                    │                          로컬 LLM (Ollama/vLLM)
                    │                          로컬 STT (Whisper)
                    │                          로컬 TTS (Kokoro/Piper)
                    │                          파일 공유
                    ├── Twilio → SMS / SIP Trunk (전화)
                    ├── SendGrid → 이메일
                    ├── LiveKit SIP → 음성 파이프라인
                    └── 민감 데이터가 인터넷 밖으로 나가지 않음
```

사용자의 기존 컴퓨터(Apple Silicon Mac 권장)에 **EasyClaw Companion**을 설치한다. Companion은 다음을 제공한다:

- **로컬 LLM 래퍼** — 고민 없이 바로 모델을 돌릴 수 있도록 Ollama/vLLM을 감싼 원클릭 앱. 모델 선택, 다운로드, 실행을 자동으로 처리한다.
- **로컬 STT/TTS** — Whisper(STT)와 Kokoro/Piper(TTS)를 로컬에서 실행한다. 전화 음성 파이프라인에서 음성 데이터가 인터넷 밖으로 나가지 않는다. LAN을 통해 SBC의 LiveKit 파이프라인에 STT/TTS 엔드포인트를 제공한다.
- **파일 공유** — SBC와 컴퓨터 간 파일 동기화. 에이전트가 컴퓨터의 특정 폴더에 접근할 수 있다.
- **LLM 엔드포인트 노출** — PicoClaw가 로컬 네트워크(LAN)를 통해 컴퓨터의 LLM에 접근한다. PicoClaw의 프로바이더 시스템이 vLLM 엔드포인트를 네이티브로 지원하므로 모델 프리픽스만 바꾸면 된다.

#### 물리적 분리의 장점

SBC와 컴퓨터는 물리적으로 별개의 기기다.

- **컴퓨터는 컴퓨터대로 쓴다** — 모델 구동 중 약간의 발열과 병목을 제외하면 평소와 동일하게 사용할 수 있다. 에이전트 프로세스가 컴퓨터의 작업 환경을 침범하지 않는다.
- **에이전트는 에이전트대로 돌아간다** — SBC는 독립적으로 24시간 구동된다. 컴퓨터를 끄면 클라우드 모드로 자동 폴백하거나, 대기 상태로 전환한다.
- **보안 경계가 명확하다** — 에이전트의 실행 환경(SBC 컨테이너)과 사용자의 작업 환경(컴퓨터)이 물리적으로 격리되어 있다. 에이전트가 컴퓨터의 파일 시스템 전체에 접근할 수 없고, 허용된 공유 폴더와 LLM 엔드포인트만 노출된다.

### 모드 비교

| | 클라우드 모드 | 로컬 모드 |
|---|---|---|
| **필요한 것** | EasyClaw + Wi-Fi + API 키 | EasyClaw + 컴퓨터 + Companion 앱 |
| **LLM 위치** | OpenRouter (클라우드) | 사용자 컴퓨터 (LAN) |
| **STT** | Deepgram (클라우드 API) | Whisper (Companion 로컬 실행) |
| **TTS** | Cartesia/ElevenLabs (클라우드 API) | Kokoro/Piper (Companion 로컬 실행) |
| **인터넷** | 필수 | 불필요 (LAN만으로 동작) |
| **데이터** | 클라우드로 전송 | 로컬 네트워크 내에서만 이동 |
| **추가 비용** | API 종량 비용 | 전기료 (컴퓨터 전력) |
| **성능** | 최신 대형 모델 사용 가능 | 컴퓨터 GPU 성능에 의존 |
| **대상** | 일반 소상공인, 프리랜서 | 민감 정보 취급, 인트라넷 환경 |

## 능동적 소통

EasyClaw는 메신저 채널(카카오톡, 텔레그램) 외에도 문자, 이메일, 전화를 직접 발신할 수 있다. 사용자가 요청하거나, 에이전트가 판단하여 능동적으로 소통한다.

### 채널

| 채널 | 기술 스택 | 용도 |
|------|-----------|------|
| 문자 (SMS) | Twilio SMS API | 예약 확인, 납기 알림, 고객 안내 등 단문 발신 |
| 이메일 | SendGrid API | 견적서, 리포트, 정산 내역 등 서식이 있는 문서 발신 |
| 전화 | LiveKit SIP + Twilio SIP Trunk | 거래처 통화, 예약 확인 전화, 고객 응대 등 음성 발신/수신 |

### 전화 음성 파이프라인

전화 채널은 LiveKit의 VoicePipelineAgent가 처리한다.

```
[전화 수신/발신]
    │
[Twilio SIP Trunk] ←→ [LiveKit SIP (SBC)]
                            │
                    [VoicePipelineAgent]
                    VAD → STT → LLM → TTS
                            │
              ┌─────────────┼─────────────┐
        [로컬 모드]                  [클라우드 모드]
    Companion 앱 (LAN)           API 키 (인터넷)
    - Whisper (STT)              - Deepgram (STT)
    - Kokoro/Piper (TTS)         - Cartesia/ElevenLabs (TTS)
    - 로컬 LLM (Ollama)          - OpenRouter (LLM)
```

- **VAD** — 음성 구간 감지. 사용자가 말하는 구간만 STT에 전달한다.
- **STT** — 음성을 텍스트로 변환. 로컬 모드에서는 Whisper, 클라우드 모드에서는 Deepgram을 사용한다.
- **LLM** — 변환된 텍스트를 에이전트가 처리하고 응답을 생성한다.
- **TTS** — 응답 텍스트를 음성으로 합성. 로컬 모드에서는 Kokoro/Piper, 클라우드 모드에서는 Cartesia/ElevenLabs를 사용한다.

### 로컬 모드와 클라우드 모드

음성 파이프라인은 LLM과 마찬가지로 두 가지 모드를 지원한다.

- **클라우드 모드** — API 키만 설정하면 Deepgram(STT)과 Cartesia/ElevenLabs(TTS)를 사용한다. 설정이 간단하고 품질이 높다.
- **로컬 모드** — Companion 앱이 Whisper(STT)와 Kokoro/Piper(TTS)를 로컬에서 실행하고, LAN을 통해 SBC에 제공한다. 음성 데이터가 인터넷 밖으로 나가지 않는다.

로컬 모드에서 Companion이 꺼지거나 응답이 느린 경우, 클라우드 API 키가 등록되어 있으면 자동으로 클라우드 모드로 폴백한다.

### AI 고지 정책

EasyClaw는 전화 통화 시 사람인 척 하지 않는다. 통화 시작 시 AI 비서임을 명확히 밝힌다.

> "안녕하세요, [상호명]의 AI 비서입니다. [용건]에 대해 연락드렸습니다."

이는 신뢰와 투명성을 위한 기본 정책이며, 에이전트 프로필에 사전 구성된다.

## 작동 방식

### 초기 설정 (1회)

별도의 모니터, 키보드, 컴퓨터 연결이 필요 없다. 스마트폰 하나면 된다.

EasyClaw는 처음 켜지면 자체 Wi-Fi AP를 띄운다. 스마트폰이나 컴퓨터로 이 AP에 접속하면 캡티브 포탈처럼 설정 페이지가 자동으로 열린다. 내장 OLED는 현재 상태와 접속할 Wi-Fi 이름을 안내한다.

**클라우드 모드**
1. EasyClaw를 전원에 연결한다 (USB-C)
2. OLED에 표시된 Wi-Fi (`EasyClaw-XXXX`)에 스마트폰/컴퓨터로 접속한다
3. 자동으로 열리는 설정 페이지에서 Wi-Fi를 설정한다
4. OpenRouter API 키를 입력한다 (신용카드 등록된 키)
5. 소통 채널을 연결한다 (카카오톡 / 텔레그램 / 이메일)
6. 선택: Twilio 계정을 연결하고 발신번호를 설정한다 (문자/전화 발신용)
7. 선택: 체크카드 정보를 등록한다 (빈 계좌 연결 권장)
8. 설정 완료 → AP가 종료되고 EasyClaw가 독립적으로 동작한다

**로컬 모드 (추가 설정)**
1. 컴퓨터에 EasyClaw Companion을 설치한다 (원클릭 설치)
2. Companion이 로컬 LLM을 자동으로 다운로드하고 실행한다
3. 설정 페이지에서 "로컬 모드"를 선택하면 같은 네트워크의 Companion을 자동 탐색한다
4. 선택: 공유 폴더를 지정한다

설정 변경이 필요할 때는 OLED의 버튼을 눌러 AP 모드를 다시 활성화하면 된다.

### 일상 사용

어떤 모드든 사용 경험은 동일하다. 익숙한 메신저로 말을 건다.

EasyClaw는 요청을 처리하는 과정에서 필요한 자료가 없으면 사용자에게 직접 요구한다. 사용자가 제공한 자료는 자동으로 정리되어 사업 데이터룸에 축적된다. 시간이 지날수록 EasyClaw는 사용자의 사업을 더 깊이 이해하고, 매번 설명하지 않아도 높은 해상도의 맥락 위에서 답변한다.

```
사용자: 이번 달 카드 매출 정리해줘
비서:   카드 매출 데이터가 필요합니다.
        POS 매출 내역 CSV나 카드사 정산 내역서를 보내주시겠어요?

사용자: [파일 첨부: 2월_카드정산.xlsx]
비서:   2월 카드 매출 정리했습니다. 총 847건, 12,340,000원입니다.
        일별 추이와 요약을 메일로 보내드릴까요?
        (정산 내역서는 데이터룸 > 매출 > 2026-02에 보관했습니다.)

사용자: 내일 오전 거래처 미팅 잡아줘
비서:   김대표님(ABC무역)께 내일 오전 10시 미팅 요청 메시지를 보냈습니다.
        확인되면 알려드리겠습니다.

사용자: 이 계약서 초안 검토해줘 [파일 첨부]
비서:   검토 완료했습니다. 3건의 수정 제안이 있습니다.
        1) 제7조 위약금 — 비율이 업계 평균 대비 높습니다
        2) 제12조 관할법원 — 상대방 소재지로 지정되어 있습니다
        3) 별첨 납품 일정 — 공휴일이 포함되어 있습니다
        수정 초안을 만들어드릴까요?
        (계약서는 데이터룸 > 계약 > ABC무역에 보관했습니다.)

사용자: 내일 예약 손님들한테 확인 문자 보내줘
비서:   내일(2/28) 예약 3건을 확인했습니다.
        김○○님(14:00), 박○○님(16:00), 이○○님(18:30)에게
        예약 확인 문자를 발송했습니다.
        "안녕하세요, [상호명]입니다. 내일 [시간] 예약 확인드립니다.
        변경/취소 시 이 번호로 회신 부탁드립니다."

사용자: ABC무역 김대표한테 전화해서 납품일 확인해줘
비서:   ABC무역 김대표님(010-XXXX-XXXX)에게 전화를 겁니다.
        [통화 중...]
        통화 완료했습니다. 김대표님이 납품일을 3/5(수)로 확정하셨습니다.
        기존 3/3에서 이틀 연기됩니다. 일정에 반영할까요?

사용자: 우리 매장 상권 분석 좀 해줘
비서:   데이터룸에 있는 사업자등록증(업종: 카페, 소재지: 성수동)과
        최근 3개월 매출 추이를 바탕으로 분석하겠습니다.
        성수동 카페 상권 리포트를 작성 중입니다...
```

마지막 예시처럼, 이전에 축적된 자료(사업자등록증, 매출 내역)가 있으면 별도 설명 없이 바로 맥락을 활용한다.

### 사업 데이터룸

EasyClaw는 사용자로부터 받은 모든 사업 자료를 자동으로 분류하여 데이터룸에 보관한다. 데이터룸은 에이전트의 장기 기억이자, 사업 자체의 정리된 아카이브다.

**자동 수집**: 사용자가 보낸 파일, 대화에서 언급된 사업 정보를 자동으로 인식하여 적절한 카테고리에 저장한다.

**자동 분류 구조** (예시):

```
데이터룸/
├── 사업 정보/        사업자등록증, 업종, 소재지, 인허가, 대표자·팀 프로필
├── 매출/            POS 내역, 카드사 정산, 현금영수증
├── 지출/            지출 내역, 영수증, 경비
├── 세무/            세금계산서, 부가세, 종합소득세 자료
├── 계약/            거래처별 계약서, 견적서, 발주서
├── 거래처/          거래처 정보, 단가표, 발주 이력
├── 고객/            고객 정보, 예약, 리뷰, 문의 이력
├── 인사/            채용, 근로계약, 급여, 스톡옵션, 조직 구성
├── 마케팅/          SNS 게시물, 이벤트, 광고 성과
```

**활용**:
- **맥락 유지** — "우리 가게"라고만 해도 어떤 업종, 어디에 있는, 매출이 얼마인 가게인지 이미 안다
- **교차 참조** — "지난달 대비 매출 변화"를 물으면 데이터룸의 월별 매출을 자동으로 비교한다
- **서류 생성** — 견적서, 계약서를 만들 때 기존 데이터룸의 사업 정보와 거래처 정보를 자동으로 채운다
- **세무 준비** — 매출, 지출, 세금계산서가 정리되어 있으므로 세무 시즌에 바로 자료를 뽑을 수 있다

### 소프트웨어 업데이트

사용자가 관리할 것은 없다. 기기가 알아서 한다.

- **EasyClaw SBC**: OTA 자동 업데이트 (PicoClaw + 스킬 + 시스템)
- **Companion 앱**: 자동 업데이트 (로컬 LLM 래퍼 + 모델)

## EasyClaw가 사전 구성하는 것

사용자가 직접 했어야 할 모든 것을 공장 출하 시점에 완료한다.

- PicoClaw 바이너리를 Docker 이미지에 탑재, systemd 서비스로 등록 (전원 ON → 자동 시작 → Gateway 모드 24시간 대기)
- 한국어 최적화 에이전트 프로필 (IDENTITY.md, SOUL.md, AGENTS.md, TOOLS.md, USER.md)
- 소상공인 업무용 스킬 사전 설치 (매출 정리, 고객 응대, 일정 관리, 서류 작성, 웹 검색 등)
- 채널 브릿지 사전 구성 (카카오톡, 텔레그램 연동)
- 통신 스킬 사전 설치 (문자 발신, 이메일 발신, 전화 발신/수신 — Twilio + SendGrid + LiveKit SIP)
- OTA 업데이트 데몬
- 초기 설정 캡티브 포탈 (AP 모드 → 브라우저에서 설정)
- 사업 데이터룸 자동 분류 스킬 (파일/정보 수집 → 카테고리별 자동 정리)
- 보안 정책 기본값 (컨테이너 격리, 커맨드 차단 목록, 경로 제한)

## 활용 사례

- **매출과 회계** — 일일 매출 정리, 지출 분류, 세금 신고 자료 준비
- **고객 응대** — 자주 묻는 질문 자동 답변, 예약 관리, 리뷰 응대
- **마케팅** — SNS 게시물 작성, 이벤트 문구 생성, 블로그 초안
- **일정 관리** — 거래처 미팅 조율, 납기일 알림, 할 일 정리
- **서류 작성** — 견적서, 계약서 초안, 공문 작성, 번역
- **시장 조사** — 경쟁사 가격 비교, 트렌드 분석, 상권 정보 수집
- **재고 관리** — 발주 시점 알림, 재고 현황 정리, 거래처 자동 발주
- **웹 작업** — 브라우저로 정보 수집, 폼 작성, 예약 대행
- **문자/이메일 발신** — 예약 확인 문자, 견적서 메일 발송, 납기 알림, 고객 안내 문자
- **전화 발신/수신** — 거래처 통화, 예약 확인 전화, 부재중 고객 콜백, AI 응대

로컬 모드 시 추가:
- **민감 문서 처리** — 계약서, 재무제표, 인사 자료를 외부 유출 없이 분석
- **규정 준수** — 개인정보보호법, 의료정보, 금융 데이터 등 외부 전송이 제한되는 정보
- **사내 지식 기반** — 내부 문서, 매뉴얼, 규정집을 공유 폴더에 넣으면 에이전트가 참조

## 왜 하드웨어인가

PicoClaw는 이미 무료이고 누구나 설치할 수 있다. 그런데 왜 굳이 물리적 기기에 담는가.

- **설치가 제품이다** — `git clone`, `make build`, `docker run` — 이 과정이 대다수 사용자에게는 넘을 수 없는 벽이다. EasyClaw는 이 벽을 공장에서 넘어준다.
- **존재감** — 책상 위에 놓인 기기는 "나에게 직원이 있다"는 심리적 효과를 준다
- **지속성** — 컴퓨터를 끄거나 앱을 닫아도 EasyClaw는 24시간 계속 일한다
- **물리적 격리** — 에이전트가 사용자의 컴퓨터와 분리된 자기만의 환경에서 돌아간다. 컴퓨터는 컴퓨터대로 쓸 수 있다.
- **신뢰** — 내 데이터를 처리하는 기기가 물리적으로 내 손 안에 있다
- **선물이 된다** — 창업하는 친구에게, 가게를 여는 부모님에게 선물할 수 있다

## EasyClaw의 가치 계층

```
┌─────────────────────────────────────────────┐
│        사용자가 보는 것                     │
│  메신저로 말 걸면 일 해주는 가상 직원       │
├─────────────────────────────────────────────┤
│        EasyClaw가 하는 것                   │
│  한국어 최적화, 소상공인 스킬, 채널 브릿지, │
│  초기 설정 마법사, OTA, 보안 정책           │
├─────────────────────────────────────────────┤
│        PicoClaw가 하는 것                   │
│  에이전트 루프, 도구 실행, LLM 통신, 메모리 │
├────────────────────┬────────────────────────┤
│    클라우드 두뇌   │      로컬 두뇌         │
│   OpenRouter API   │  Companion + 로컬 LLM  │
│    (기본)          │  사용자 컴퓨터 (선택)  │
├────────────────────┴────────────────────────┤
│        하드웨어                             │
│  Linux SBC (LicheeRV Nano 급) + Docker      │
└─────────────────────────────────────────────┘
```

EasyClaw의 고유 가치는 두 번째 계층이다. PicoClaw와 최종 사용자 사이의 간극을 메우는 **구성(configuration), 최적화(optimization), 패키징(packaging)** 레이어.
