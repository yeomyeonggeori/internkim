# 조직도 그룹 내부 직원 계층 정렬 설계

## 목표

조직도에서 그룹 내부 직원의 보고 관계가 먼저 드러나도록 정렬한다. 그룹 리더를 가장 위에 표시하고, 각 직원의 직속 하위 직원을 바로 뒤에 배치한다. 같은 직속 상관 아래 직원끼리는 입사일과 이름으로 순서를 결정한다.

## 현재 동작

그룹 내부 직원은 보고 관계와 관계없이 입사일 오름차순으로 정렬된다. 입사일이 같으면 이름순이며, 입사일이 없는 직원은 마지막에 배치된다. 그룹 책임자와 회사 책임자는 `supervisorID`로 판별하지만 목록에서는 배지만 표시한다.

## 정렬 규칙

1. 그룹 내부에서 직속 상관이 없거나 직속 상관이 해당 그룹에 없는 직원을 최상위 직원으로 본다.
2. 최상위 직원끼리는 입사일 오름차순과 이름순으로 정렬한다.
3. 각 직원을 표시한 직후 그 직원의 직속 하위 직원들을 재귀적으로 배치한다.
4. 같은 직속 상관을 둔 직원끼리는 입사일 오름차순과 이름순으로 정렬한다.
5. 입사일이 없는 직원은 같은 형제 목록에서 입사일이 있는 직원 뒤에 배치한다.
6. 직원 이름 비교는 현재 규칙을 유지해 한글 이름, 영문 이름, 그 밖의 이름 순으로 처리한다.

최상위 직원이 한 명이면 기존 그룹 책임자 판별 결과와 같은 직원이 가장 먼저 표시된다. 최상위 직원이 여러 명이면 특정 그룹 리더를 임의로 정하지 않고 입사일과 이름으로 각 최상위 직원의 하위 트리를 정렬한다.

## 구성 요소

### 직원 정렬 모듈

`web/src/lib/orgchart/person-order.ts`가 그룹 직원의 계층 정렬을 소유한다. 기존 직원 비교 함수는 같은 계층의 직원 순서를 결정하는 비교자로 유지하고, 그룹의 직원 배열을 받아 보고 관계 순서로 반환하는 함수를 추가한다.

정렬 함수는 그룹 직원의 `userID`와 `supervisorID`로 직속 하위 직원 목록을 구성하고, 방문한 직원을 추적하면서 최상위 직원부터 깊이 우선으로 순회한다. 원본 배열은 변경하지 않는다.

### 조직 트리 모델

`web/src/routes/orgchart/orgchart-organization-tree-model.ts`는 그룹별 `directRecords`와 `aggregateRecords`를 만들 때 직원 정렬 모듈을 호출한다. 이 파일에는 새로운 정렬 규칙을 구현하지 않고 호출 연결만 둔다.

### 화면 표시

`web/src/routes/orgchart/orgchart-people-group.svelte`는 전달받은 직원 순서대로 렌더링하므로 변경하지 않는다. 회사 책임자와 조직 책임자 배지 동작도 유지한다.

## 비정상 관계 처리

그룹 외부 직원을 상관으로 가진 직원은 해당 그룹의 최상위 직원으로 취급한다. 방문 과정에서 이미 처리한 직원은 다시 처리하지 않아 순환 관계로 인한 무한 순회를 막는다. 정상적인 최상위 경로에서 도달하지 못한 직원이 있으면 누락되지 않도록 기존 입사일과 이름순으로 마지막에 배치한다.

## 범위 제외

- 조직 및 그룹 자체의 표시 순서.
- 직원 카드의 시각적 들여쓰기나 연결선.
- 그룹 책임자를 지정하는 별도 데이터 모델.
- 관리자 화면의 직속 상관 편집 규칙.

## 검증

- 단일 그룹 리더가 가장 먼저 표시되는지 확인한다.
- 그룹 리더, 중간 관리자, 하위 직원의 다단계 보고 관계가 깊이 우선 순서로 표시되는지 확인한다.
- 같은 직속 상관 아래 직원들이 입사일과 이름순으로 정렬되는지 확인한다.
- 입사일이 없는 직원, 그룹 외부 상관, 여러 최상위 직원, 순환 관계에서도 모든 직원이 한 번씩 표시되는지 확인한다.
- 조직 트리 모델이 그룹별 직원과 하위 그룹 집계 직원에 동일한 정렬 규칙을 적용하는지 확인한다.
- 조직도 단위 테스트, Svelte 타입 검사, 조직도 E2E를 실행한다.
- 브라우저에서 그룹 리더와 다단계 보고 관계의 실제 표시 순서를 확인한다.

새 의존성이나 API 변경은 없다.
