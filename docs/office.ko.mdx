이사회 보고용 발표자료를 PDF로, CSV를 요약한 엑셀 파일을, 워드로 쓴 제안서를
요청하면 에이전트는 `office` 스킬 하나로 처리합니다. 이 스킬은 호스트에서
명령줄 도구로 실행되고 단계마다 결과를 JSON으로 돌려줍니다. 그래서 에이전트는
무엇을 만들었는지, 무엇이 잘못됐는지, 문제마다 어떤 연산으로 고치면 되는지 알 수
있습니다. 파워포인트나 엑셀 없이도, 브라우저나 데스크톱 앱 없이도 동작합니다.
스킬이 그리는 데 쓰는 폰트를 함께 담고 있어서 노트북, Mac Studio, 회사의 리눅스
장비 어디서든 페이지가 똑같이 나옵니다.

같은 스킬이 [플러그인](/ko/docs/plugin)에도 들어 있으므로, 내 컴퓨터에서 돌아가는
코딩 에이전트도 똑같은 파일을 만듭니다.

## 발표자료 [#decks]

발표자료에는 미리 정해 둔 테마도, 레이아웃 키트도, 기성 그래픽도 없습니다.
에이전트는 요청마다 발표자료를 새로 디자인합니다. 작업 단계는
[GenOffice](https://github.com/genspark-ai/genoffice)(Apache-2.0, 플러그인의
`NOTICE`에 출처 표기)를 바탕으로 고친 것입니다. 단계마다 파일을 하나씩 쓰고,
다음 단계로 넘어가기 전에 검사합니다.

| 단계 | 파일 | 담는 내용 |
|---|---|---|
| 스타일 시트 | `DESIGN.md` | 강조색을 두 개까지 쓰는 팔레트, 페이지 종류별 배경, 글자 크기, 스타일 이름 한 줄 |
| 개요 | `outline.json` | 핵심 메시지와 페이지별 제목, 종류, 요지, 수치, 필요한 사진 |
| 페이지 | `pages/01.html`, `pages/02.html`, … | 파일 하나에 한 페이지씩, 개요의 해당 항목을 보고 씁니다 |
| 빌드 | `build/<이름>.pptx` | 파워포인트 파일과, 같은 위치에 만든 PDF |

스타일 시트는 수치로 잴 수 있는 것만 검사합니다. 색 값이 올바른지, 글자 크기가
읽을 수 있는 최소 크기 이상인지, 글자와 배경의 대비가 충분한지 봅니다.

개요에 들어가는 숫자는 모두 이름, 값, 단위를 갖춘 수치로 적습니다. 페이지를
만들기 전에 먼저 판단 모델(jev)이 개요의 글을 요청 내용과 첨부 파일에 견주어
읽고, 지어낸 숫자나 출처 문구, 슬로건처럼 근거 없는 내용을 돌려보냅니다. 이어서
같은 모델을 발표자료 전체에 대해 한 번 더 호출해, GenOffice의 이름 붙은 구성
목록에서 페이지마다 레이아웃을 고릅니다. 목록에는 표지, 세 칸 카드, 큰 숫자
하나, 타임라인, 2단, KPI 카드 한 줄, 시사점을 곁들인 차트, 사진 레이아웃, 마무리
페이지가 있습니다. 본문 페이지 두 장이 연달아 같은 레이아웃을 쓰는 일은 없고,
발표자료 하나에 레이아웃을 적어도 세 가지 씁니다. 레이아웃이 정하는 것은 구성의
틀뿐이고, 비율과 요소, 그 크기와 색은 여전히 모델이 정합니다.

페이지 제목은 개요의 해당 항목에서 가져와 빌드 단계에서 채워 넣으므로, 다른
페이지의 제목이 잘못 들어갈 수 없습니다. 차트는 그 항목의 수치만 단위와 함께
그리며, 한 축에 단위가 둘 섞인 차트는 거부됩니다. 페이지를 하나 쓸 때마다
`office check pages/NN.html`이 그 페이지만 따로 검사해, 상자나 페이지 밖으로
넘친 내용, 서로 겹친 요소, 잘린 글자, 대비 문제, 최소 크기보다 작은 글자를
찾습니다.

`office create build/<이름>.pptx .`은 모든 단계를 다시 검사하고, 모든 페이지를
렌더링해 잰 뒤, 에이전트가 따를 판정 하나를 내립니다.

| 판정 | 에이전트가 하는 일 |
|---|---|
| `ACCEPTABLE` | 지정된 파일을 전달합니다. 남은 지적은 참고 사항입니다 |
| `FIX ROUND n OF 2` | 나열된 결함만 해당 페이지 파일에서 고치고 다시 빌드합니다 |
| `STOP FIXING` | 파일을 전달하고, 남은 문제를 알립니다 |

그다음 이미지를 볼 수 있는 판단 모델(clef)이 렌더링된 슬라이드를 한 장씩
살피고, 발표자료 전체에서 레이아웃이 반복되지 않는지도 확인합니다. 겹침,
비좁거나 남는 공간, 어긋난 정렬, 읽기 어려운 차트, 부적절한 사진처럼 객관적인
결함만 알립니다. 호스트는 지적받은 페이지만 최대 두 차례 다시 쓰고, 문제가 없는
페이지는 건드리지 않습니다. 파일을 전달할 때는 마지막 안전장치로 근거 확인
단계가 글을 한 번 더 읽어, 출처가 뒷받침하지 않는 값은 빈칸으로 남기고 답장에서
채워 드리겠다고 제안합니다.

InternKim은 요청을 보고 발표자료의 서체를 고릅니다. 기본은 Paperlogy이고,
Freesentation이나 A2Z를 고르기도 합니다. 사용자가 지정한 서체는 첨부 파일,
데이터룸, Google Fonts에서 찾아 파일에 포함하고, 찾지 못하면 Paperlogy로 만든 뒤
답장에서 그 사실을 알려 드립니다. 회사 로고는 표지와 마무리 페이지에 들어갑니다.
사진은 요청에 첨부된 파일과 요청자가 볼 수 있는 데이터룸 이미지에서 가져오며,
사진이 없는 페이지에 빈 자리표시 상자를 넣지 않습니다.

`.pptx` 안의 글자는 그대로 편집할 수 있고, 차트와 표는 데이터가 담긴 파워포인트
차트와 표로 들어가며, 폰트도 파일에 포함됩니다.

다른 사람에게서 받은 `.pptx`는 `office apply`로 파일을 직접 고치고,
`office check`로 미리 보며 검사합니다. 검사에서 나온 레이아웃 문제에는 그것을
해결하는 연산이 함께 제시되고, 연산 하나로 해결할 수 없으면 그렇다고 알려 줍니다.

## 스프레드시트 [#spreadsheets]

CSV는 `office create`를 거쳐 열마다 데이터 형식이 지정된 통합문서가 되고,
`office apply`가 수식, 조건부 서식, 데이터 유효성 검사, 표, 차트, 피벗 테이블,
페이지 설정처럼 요청에 필요한 요소를 더합니다. 수식은 파일을 저장할 때 미리
계산해 두므로, 재계산을 하지 않는 뷰어로 열어도 숫자가 보입니다.

`office check`는 수식 오류, 편집 후 갱신되지 않은 값, 텍스트로 저장된 숫자,
참조하는 데이터가 없는 차트, 필요 이상으로 여러 페이지에 걸치거나 너무 작게
인쇄되는 시트를 해결 방법과 함께 알려 줍니다. `office render`는 인쇄될 페이지를
이미지로 그려 에이전트가 직접 확인하게 합니다.

## 문서와 PDF [#documents]

워드 문서는 표, 그림, 차트를 넣을 수 있는 Markdown으로 작성하거나, 연산 단위로
하나씩 고칩니다. 수정 내용은 작성자 이름으로 변경 내용 추적을 남겨 나중에
수락하거나 거부할 수 있고, 메모를 달고 답글을 쓰고 해결 처리할 수도 있습니다.
`office render`는 워드와 같은 방식으로 페이지를 나누고, `office check`는 그
결과를 바탕으로 페이지 맨 아래에 홀로 남은 제목을 파일을 첨부하기 전에 찾아냅니다.

PDF는 레이아웃 명세로 만들 수 있고, 페이지 단위로 읽거나 이미지로 렌더링하거나
섹션 페이지를 덧붙일 수 있습니다. 스캔한 PDF는 `--ocr`로, 암호가 걸린 PDF는
`--password`로 읽습니다. `office convert`는 Markdown, 워드, HTML, PDF, 통합문서,
CSV, 파워포인트 사이에서 형식을 변환하며, 변환 경로마다 무엇이 유지되는지는
`office guide convert`에서 볼 수 있습니다.

견적서나 계약서 같은 회사 서식은 `office merge`로 회사 레터헤드 위에 채우고,
`office check`가 행별 금액, 합계, 세액, 한글 금액 표기를 검사합니다. 서식
목록은 `office guide form`에서 볼 수 있습니다.

## 결과 [#results]

모든 명령은 JSON 결과를 하나 출력합니다. 여기에는 `ok`, `warning`, `error` 중
하나인 상태, 요약, 이슈 목록이 들어 있습니다. 이슈마다 고정된 코드, 위치, 해야
할 일을 설명하는 문장, 그리고 그 변경을 수행하는 연산 목록인 `fix`가 붙습니다.
명령, 필드, 레이아웃 이름을 잘못 입력하면 가장 비슷한 올바른 이름을 알려 줍니다.
여러 연산을 한 번에 보내면 전부 적용되거나 하나도 적용되지 않으며, `--mode`로
적용할 수 있는 것만 적용하도록 요청할 수 있습니다.

## 필요한 것 [#requirements]

`office setup`은 Python 패키지, 페이지 렌더러, OCR 엔진처럼 스킬에 필요한 것을
고정된 버전으로 스킬 파일과 같은 위치에 설치합니다. 실행하려면 Python 3,
[uv](https://docs.astral.sh/uv/), 그리고 Bun 또는 Node 18 이상이 필요하며,
[호스트 설치](/ko/docs/running-the-host) 과정에서 이 명령이 실행됩니다. 다른
명령은 아무것도 설치하지 않고, setup 전에 실행하면 먼저 setup을 실행하라고
안내합니다.

폰트는 SIL Open Font License로 배포되며 스킬에 함께 들어 있으므로, 호스트에
설치된 폰트에는 의존하지 않습니다. 폰트 목록은 `office guide`에서 볼 수 있습니다.
