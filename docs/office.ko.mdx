이사회 보고용 발표자료 PDF, CSV를 요약한 엑셀, 워드로 쓴 제안서를 요청하면
에이전트는 `office` 스킬 하나로 처리합니다. 이 스킬은 호스트에서 명령줄 도구로
돌고 단계마다 JSON 결과를 돌려주므로, 에이전트는 무엇을 만들었는지, 무엇이
잘못됐는지, 문제마다 어떤 연산으로 고치는지를 봅니다. 오피스 프로그램도,
브라우저도, 데스크톱 앱도 필요 없습니다. 스킬이 그릴 때 쓰는 폰트를 직접 들고
다니므로 노트북에서도, Mac Studio에서도, 회사의 리눅스 장비에서도 같은 페이지가
나옵니다.

같은 스킬이 [플러그인](/ko/docs/plugin)에도 들어 있어서, 내 컴퓨터의 코딩
에이전트도 같은 파일을 만듭니다.

## 발표자료 [#decks]

발표자료에는 미리 정해 둔 테마도, 레이아웃 키트도, 기성 그래픽도 없습니다.
에이전트는 요청마다 발표자료를 새로 디자인하며, 단계는
[GenOffice](https://github.com/genspark-ai/genoffice)(Apache-2.0, 플러그인의
`NOTICE`에 출처 표기)에서 가져와 고쳤습니다. 단계마다 파일 하나를 쓰고, 다음
단계로 가기 전에 검사합니다.

| 단계 | 파일 | 담는 것 |
|---|---|---|
| 스타일 시트 | `DESIGN.md` | 강조색 두 개까지의 팔레트, 페이지 종류별 배경, 글자 크기, 스타일을 말하는 한 줄 |
| 아웃라인 | `outline.json` | 핵심 메시지, 그리고 페이지마다 제목, 종류, 요지, 수치, 필요한 사진 |
| 페이지 | `pages/01.html`, `pages/02.html`, … | 파일 하나에 한 페이지, 아웃라인 항목을 보고 씁니다 |
| 빌드 | `build/<이름>.pptx` | 파워포인트 파일과 그 옆의 PDF |

스타일 시트는 잴 수 있는 것만 검사합니다. 색 값이 올바른지, 글자 크기가 읽을 수
있는 최소 크기 이상인지, 글자와 배경의 대비가 충분한지 봅니다.

아웃라인의 숫자는 모두 이름, 값, 단위를 갖춘 수치로 적습니다. 페이지를 하나도
만들기 전에 판단 모델(jev)이 아웃라인의 글을 요청과 첨부 파일에 비추어 읽고,
꾸며 낸 숫자, 출처 문구, 슬로건처럼 근거가 없는 것을 돌려보냅니다. 같은 모델이
덱 전체에 대해 한 번 더 불려 GenOffice의 구성 목록에서 페이지마다 레이아웃을
고릅니다. 표지, 세 칸 카드, 큰 숫자 하나, 타임라인, 두 단, KPI 카드 한 줄,
인사이트를 곁들인 차트, 사진 레이아웃, 마무리 페이지가 있습니다. 본문 페이지가
연달아 같은 레이아웃을 쓰는 일은 없고, 한 덱에 적어도 세 종류를 씁니다.
레이아웃은 구성의 이름일 뿐이고, 비율, 요소, 크기, 색은 여전히 모델이 정합니다.

페이지 제목은 아웃라인 항목에서 오고 빌드가 채워 넣으므로, 다른 페이지의
제목이 들어갈 수 없습니다. 차트는 그 항목의 수치만 단위와 함께 그리며, 한 축에
단위가 둘 섞인 차트는 거부됩니다. 페이지를 하나 쓸 때마다
`office check pages/NN.html`이 그 페이지만 잽니다. 상자나 페이지 밖으로 넘친
내용, 서로 겹친 요소, 잘린 글자, 대비, 최소 크기보다 작은 글자를 찾습니다.

`office create build/<이름>.pptx .`은 모든 단계를 다시 검사하고, 모든 페이지를
그려서 잰 뒤, 에이전트가 따를 판정 하나로 끝납니다.

| 판정 | 에이전트가 하는 일 |
|---|---|
| `ACCEPTABLE` | 지정된 파일을 전달합니다. 남은 지적은 참고 사항입니다 |
| `FIX ROUND n OF 2` | 나열된 결함만 해당 페이지 파일에서 고치고 다시 빌드합니다 |
| `STOP FIXING` | 전달하고 남은 문제를 밝힙니다 |

그다음 이미지를 읽는 판단 모델(clef)이 그려진 슬라이드를 한 장씩 보고, 덱
전체에서 반복되는 레이아웃이 없는지 봅니다. 겹침, 비좁거나 낭비된 공간, 어긋난
정렬, 읽을 수 없는 차트, 잘못된 사진처럼 객관적인 결함만 알립니다. 호스트는
지적된 페이지만 두 번까지 다시 쓰고, 문제가 없는 페이지는 건드리지 않습니다.
파일을 전달할 때는 마지막 안전장치로 주장 검사가 글을 한 번 더 읽고, 근거가
없는 값은 빈칸으로 남겨 답장에서 채워 드리겠다고 제안합니다.

InternKim은 요청을 보고 발표자료의 서체를 고릅니다. 기본은 Paperlogy이고,
Freesentation이나 A2Z를 고르기도 합니다. 사용자가 이름을 댄 서체는 첨부 파일, 데이터룸, Google
Fonts에서 찾아 파일에 넣고, 찾지 못하면 Paperlogy로 만든 뒤 답장에서 그 사실을
알립니다. 회사 로고는 표지와 마무리 페이지에 들어갑니다. 사진은 요청의 첨부
파일과 요청자가 읽을 수 있는 데이터룸 이미지에서 가져오며, 사진이 없는 자리에
빈 상자를 넣지 않습니다.

`.pptx`에서 글자는 편집 가능한 글자로 남고, 차트와 표는 데이터를 담은 네이티브
차트와 표가 되며, 폰트가 파일 안에 들어갑니다.

누군가 건넨 `.pptx`는 `office apply`로 그 자리에서 고치고,
`office check`로 미리 보고 잽니다. 보고된 레이아웃 문제에는 그것을 해결하는
연산이 붙거나, 연산 하나로는 해결할 수 없다는 설명이 붙습니다.

## 스프레드시트 [#spreadsheets]

CSV는 `office create`로 타입이 정해진 통합문서가 되고, `office apply`가
요청에 필요한 것을 더합니다. 수식, 조건부 서식, 유효성 검사, 표, 차트, 피벗 표,
페이지 설정이 그것입니다. 수식은 파일을 쓸 때 계산되므로, 다시 계산하지 않는
뷰어로 열어도 숫자가 보입니다.

`office check`는 수식 오류, 편집 뒤 갱신되지 않은 값, 글자로 저장된 숫자,
아무것도 읽지 않는 차트, 필요 이상으로 여러 쪽에 걸치거나 너무 작게 인쇄되는
시트를 해결 방법과 함께 알려 줍니다. `office render`는 인쇄될 쪽을 그려서 에이전트가
직접 보게 합니다.

## 문서와 PDF [#documents]

워드 문서는 표, 그림, 차트를 담은 Markdown으로 쓰거나 연산 단위로 고칩니다.
고친 내용을 작성자 이름으로 변경 추적하고 나중에 수락하거나 거부할 수 있으며,
메모를 달고 답하고 해결할 수 있습니다. `office render`는 워드처럼 쪽을
나누고, `office check`는 그 쪽 나눔으로 쪽 끝에 홀로 남은 제목을 첨부 전에
잡아냅니다.

PDF는 레이아웃 명세로 만들고, 쪽별로 읽고, 이미지로 그리고, 섹션 쪽을 덧붙일 수
있습니다. 스캔한 PDF는 `--ocr`로, 잠긴 PDF는 `--password`로 읽습니다.
`office convert`는 Markdown, 워드, HTML, PDF, 통합문서, CSV, 파워포인트 사이를
옮기며, `office guide convert`가 경로마다 무엇을 유지하는지 보여 줍니다.

견적서와 계약서 같은 회사 서식은 `office merge`로 회사 레터헤드에 채우고,
`office check`가 행 금액, 합계, 세금, 한글 금액 표기를 검사합니다. 서식 목록은
`office guide form`이 보여 줍니다.

## 결과 [#results]

모든 명령은 JSON 결과 하나를 출력합니다. `ok`, `warning`, `error` 중 하나인
상태, 요약, 이슈가 들어 있습니다. 이슈마다 바뀌지 않는 코드, 위치, 할 일을 적은
문장, 그리고 그 변경을 하는 연산 목록인 `fix`가 있습니다. 명령, 필드, 레이아웃
이름을 잘못 쓰면 가장 가까운 올바른 이름으로 답합니다. 연산 묶음은 `--mode`로
최선 적용을 요청하지 않는 한 전부 적용되거나 하나도 적용되지 않습니다.

## 필요한 것 [#requirements]

`office setup`이 스킬에 필요한 것을 고정된 버전으로 스킬 옆에 설치합니다.
Python 패키지, 페이지 렌더러, OCR 엔진이 그것입니다. Python 3,
[uv](https://docs.astral.sh/uv/), Bun이나 Node 18 이상이 필요하고,
[호스트 설치](/ko/docs/running-the-host)가 이 명령을 실행합니다. 다른 명령은
아무것도 설치하지 않으며, setup 전에는 먼저 실행하라고 알립니다.

폰트는 SIL Open Font License를 따르며 스킬과 함께 다니므로, 호스트에 설치된
폰트에 기대는 것이 없습니다. 목록은 `office guide`가 보여 줍니다.
