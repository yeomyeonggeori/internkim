무엇이 일어나도 되는지를 두 가지가 정하고, 각각은 자기 영역에서 완결됩니다.

| | 지키는 것 | 키 | 집행자 |
|---|---|---|---|
| Row level security | 회사의 기록 | `member` | 데이터베이스 |
| POSIX 권한 | 파일과 실행 | 사람마다 하나의 사용자 | 운영체제 |

어느 쪽도 상대를 흉내 내지 않고, 그 위에서 애플리케이션 코드로 접근을 정하는
세 번째 층은 없습니다.

## 기록 [#records]

기록에 대한 모든 읽기와 쓰기는 멤버로서 일어납니다. 앱은 로그인한 사람의
세션으로, 에이전트는 대신 행동하는 그 사람을 위해 컨트롤 플레인이 발급한
세션으로 합니다. 이것을 우회할 수 있는 단 하나의 키는 컨트롤 플레인의 서버
쪽에 살고, 그 키가 발급하는 것은 세션입니다.

에이전트는 컨트롤 플레인이 지정한 멤버 세션으로 움직입니다. 그 멤버의 기록을
보고, 관리자 세션으로 움직일 때는 관리자의 기록을 봅니다.

## 파일과 실행 [#files-and-execution]

사람은 진짜 운영체제 사용자이고 서클은 진짜 그룹입니다. 사람은 안정적인
`bc_person_<shortID>` 사용자가 되고, 서클은 `bc_circle_<circleID>` 그룹이
됩니다. 에이전트는 그 사람의 일을 그 사용자로 실행하므로, 워크스페이스도,
터미널도, 그가 띄우는 어떤 프로그램도 평범한 파일 권한에 갇힙니다.

이 장치에는 좁은 허리가 하나 있습니다. blueclaw 서비스는 요청자의 파일을 직접
만지지 않습니다. 모든 워크스페이스 읽기, 쓰기, 프로세스 실행은
`WorkspaceActor → blueclaw-posix-helper`로 내려갑니다. 헬퍼는
`root:root 4755` setuid 다리이고, 실행할 수 있다는 것이 곧 권한은 아닙니다.
자신을 부른 real UID가 `root`나 `blueclaw`인지 확인한 뒤, 무엇을 하기 전에
요청자의 UID, GID, 보조 그룹으로 내려갑니다. 호스트 이미지는 헬퍼를
`/usr/local/bin/blueclaw-posix-helper`에 설치하고, 디바이스는 같은 바이너리를
게스트 rootfs 안에 둡니다. 헬퍼가 없으면 blueclaw는 워크스페이스 도구를 모두
거부합니다. 양쪽 모두 blueclaw 서비스 자신은 `blueclaw` 사용자로 돕니다. 터미널이
root로는 실행을 거부하기 때문입니다.

| 워크스페이스 경로 | 권한 모델 | 담는 것 |
|---|---|---|
| `/workspace/private/people/<personID>` | 요청자 전용, `2770` | 개인 공간: `tmp/` 초안, `artifacts/` 결과물 |
| `/workspace/circles/<circleID>` | 서클 그룹, `2770` | 의도적인 팀 공유 |
| `/workspace/shared/public` | 공유 폴리시 | 외부인에게 보여도 안전한 내용 |
| `/workspace/shared/cache/dependencies` | 공유 캐시 그룹 | 패키지 캐시만 |
| `/workspace/skills` | 읽기와 실행 | 내장 스킬 소스 |
| `/workspace/.blueclaw` | 서비스 소유 | 데이터베이스, 로그, 내부 상태 |

허용 명령 목록도, 경로 문자열 필터도 없습니다. 시스템을 바꿀 명령은 그것을
실행하는 사용자가 그럴 수 없기 때문에 실패하는데, 그 사람이 셸에서 직접 쳐도
실패하는 이유와 같은 이유입니다.

## 둘이 만나는 단 한 곳 [#the-one-place-they-meet]

사람은 기록에서는 `member`이고 호스트에서는 사용자입니다. 매핑 하나가 그 두
사실을 잇고, 그것이 두 경계 사이의 유일한 다리입니다. 신원 해석은
정확합니다. 식별자는 일치하거나, 일치하지 않거나 둘 중 하나입니다.

## 이것이 배제하는 것 [#what-this-rules-out]

- 경로 문자열 매칭으로 접근을 정하는 것. 소유권과 모드 비트가 정합니다.
- 단어 매칭으로 의미를 정하는 것. 구조화된 답과 정확한 식별자 해석이 대신
  합니다.
- 데이터베이스도 운영체제도 모르는, 애플리케이션 코드 속 두 번째 권한 모델.
