회사 호스트는 arm64 또는 amd64의 Debian 13, Ubuntu 22.04 또는 24.04, Fedora,
RHEL 호환 10(Rocky, AlmaLinux), Arch Linux, 그리고 Homebrew를 설치한 Apple
실리콘 Mac에서 실행됩니다. Ubuntu 22.04의 저장소에는 에이전트의 기억 검색에 필요한
pgvector가 없어서, 그곳에서는 PostgreSQL의 자체 apt 저장소를 추가하고 거기서
PostgreSQL 15와 그 pgvector를 받습니다. Linux 패키지는 glibc 2.35 이상이 필요합니다. 인터넷에
연결하고 계속 켜 두어야 합니다. 설치 프로그램은 Linux의 systemd나 macOS의
launchd에 서비스를 등록합니다. 공개 주소, 외부에서 들어오는 포트, Docker 설치는
필요하지 않습니다.

## 설치하기

회사 설정 화면에서 연결 파일을 받은 다음 실행하세요.

```bash
curl -fsSL https://intern.kim/install.sh | sh -s -- host
sudo internkim install ~/Downloads/internkim-host.json
```

첫 명령은 apt, dnf, pacman 또는 Homebrew 패키지를 설치합니다. Linux에서는 이
컴퓨터에 맞는 패키지를 저희 GitHub 릴리스에서 받아 릴리스의 `SHA256SUMS`와
대조한 다음 패키지 관리자에게 넘깁니다. Mac에서는 저희 Homebrew 탭
`yeomyeonggeori/tap`을 추가하고 `internkim` formula를 설치합니다. 이 formula의
bottle은 같은 GitHub 릴리스에서 받고, formula에 적힌 체크섬과 대조합니다. 둘째 명령은 회사를 설정하고 OpenRouter
API 키를 받은 뒤 호스트 서비스를 등록합니다. 컴퓨터가 켜지면 서비스가 자동으로
시작하고, 서비스가 종료되면 다시 시작합니다. 설치가 끝나면 화면에 나온 회사 설정
주소에서 연결 확인을 누르세요.

Linux에서는 연결 파일 없이도 됩니다. 첫 명령만 실행하면 컴퓨터는 회사를 기다리며
같은 네트워크의 `http://<컴퓨터>.local:18088/`에 8자리 연결 코드를 띄웁니다.
`sudo internkim box code`로도 같은 코드를 볼 수 있습니다. 같은 네트워크에 있는
관리자가 회사 설정 화면에 코드를 넣고, 컴퓨터 키의 마지막 네 글자를 확인한 뒤
연결을 누르면 됩니다. 그다음 설정 화면이 OpenRouter 키를 묻습니다. 연결이 어떻게
이뤄지고 연결 해제가 무엇을 되돌리는지는 [김미니](/ko/kim-mini)에 있습니다.

## 업그레이드하기

첫 명령을 다시 실행하세요. Linux에서는 채널이 지금 가리키는 릴리스를 지금 버전
위에 설치하고, macOS에서는 Homebrew가 formula를 업그레이드합니다. 회사와 데이터는
그대로 남습니다. 기본 채널은 최신 정식 릴리스입니다. Linux에서 사전 릴리스까지
포함해 가장 새 릴리스를 따라가려면 `--channel testing`을 붙이세요.

```bash
curl -fsSL https://intern.kim/install.sh | sh -s -- host --channel testing
```

탭에는 최신 정식 릴리스만 올라가므로 Mac은 기본 채널을 따라갑니다.

## 제거하기

```bash
sudo apt remove internkim     # Debian, Ubuntu
sudo dnf remove internkim     # Fedora, RHEL 호환
sudo pacman -R internkim      # Arch Linux
```

패키지를 제거하면 호스트 서비스가 멈추고 비활성화되며, 프로그램 파일과 호스트의
Python 런타임이 지워집니다. Ubuntu 22.04에서는 PostgreSQL의 apt 저장소를 남겨
둡니다. 호스트의 데이터베이스를 만든 PostgreSQL 15가 그 저장소에서 업데이트를 받기
때문입니다. 저장소를 지우는 명령은 패키지를 제거할 때 출력되니, 데이터베이스를 지운
뒤에 실행하면 됩니다. 다른 배포판에서는 설치할 때 패키지 저장소나 서명 키를 추가하지 않습니다. 회사는
컴퓨터에 남습니다. `/var/lib/internkim`에는
호스팅 서비스에서 이 회사를 증명하는 키와 사람마다 메시지에 서명하는 시드가 있고,
`/var/lib/internkim-postgres`와 `/var/lib/internkim-cache`에는 호스트의 데이터베이스와
캐시가 있습니다. 패키지를 다시 설치하면 같은 회사로 돌아옵니다. Debian과 Ubuntu에서
`sudo apt purge internkim`을 쓰면 `/etc/internkim`의 설정도 지웁니다.

두 키는 다시 발급할 수 없으므로 회사를 지우는 일은 직접 하세요.

```bash
sudo rm -rf /var/lib/internkim /var/lib/internkim-postgres /var/lib/internkim-cache
```

## 서비스 확인하기

Linux에서는 systemd에서 상태와 로그를 확인합니다.

```bash
systemctl list-units 'internkim*' 'blueclaw*' 'buzz*'
systemctl status internkim-relay
journalctl -u internkim-relay -n 50 --no-pager
```

macOS에서는 `launchctl print system/kim.intern.<service>`로 서비스를 확인합니다.
로그는 `/var/log/internkim/`에 있습니다.

## 설정

설치 프로그램은 회사 연결 정보와 생성된 자격증명을 접근이 제한된 호스트 데이터
디렉터리에 저장합니다. 대부분은 이 파일을 직접 고칠 필요가 없습니다. 선택 설정은
`/etc/internkim/company-host.env`에 둡니다. 지원하는 변수와 기본값은 생성된
[호스트 설정 참조](https://github.com/yeomyeonggeori/internkim/blob/main/host/README.md)에
있습니다. API 키와 연결 파일은 설정 파일에 넣지 마세요.

## 로컬 데이터

회사 컴퓨터에는 에이전트의 대화와 업무 이력, 기억, 워크스페이스 파일, 전달 대기
메시지가 저장됩니다. 호스팅된 회사 기록과는 별개입니다. 호스트를 백업하거나
교체하기 전에 [무엇이 어디 사는지](/ko/what-lives-where) 확인하세요.

## 답 크기

전송 한도를 넘는 답에는 릴레이가 바이트 수와 함께 `413`으로 응답합니다. 기본
상한은 3,000,000바이트이며 `ANSWER_BYTE_CEILING`으로 바꿀 수 있습니다. 0 이하의
값은 호스트 시작을 막습니다. 프로필 사진 한도는 base64 인코딩으로 크기가
늘어나는 만큼 이 상한에서 계산합니다.

## 네트워크 연결

호스트는 바깥으로 연결하고 로컬 인터페이스에서만 요청을 받습니다. 아직 회사가
없는 Linux 호스트만 예외로, 연결될 때까지 포트 18088에 연결 코드를 띄웁니다.
컴퓨터 관리는 같은 네트워크의 셸이나 회사가 관리하는 원격 접속 방법을 사용하세요.

Linux에서 패키지를 설치하거나 업그레이드할 때는 호스트가 쓰는 하나뿐인 Python
런타임을 `github.com`에서 받아 `/opt/internkim/python`에 두고, 첨부 문서를 읽는
고정된 라이브러리를 `pypi.org`와 `files.pythonhosted.org`에서 내려받습니다. 둘 중
하나라도 닿지 않으면 설치가 멈추고 무엇을 받지 못했는지 알려 줍니다. 배포판의
Python은 필요하지 않습니다. 스킬도 같은 런타임에서 각 사람 명령의 `python3`로
돌고, 처음 실행할 때 필요한 라이브러리를 PyPI에서 받습니다.
