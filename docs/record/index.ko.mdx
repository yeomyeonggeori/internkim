`https://api.intern.kim/v1`의 API가 호출자가 써야 할 표면입니다. 그 아래는
Postgres이고, internkim의 상당 부분이 웹 앱이 아니라 거기에 쓰여 있습니다.
`attendance_add` 같은 도구는 호출자를 해석하고, 쓸 권한이 있는지 판정하고,
쓰거나 아니면 관리자에게 요청된 무언가로 바꾸는 일을 한 함수 안에서 다 합니다.

여기엔 비용이 있습니다. SQL에 쓰인 규칙은 그 위의 TypeScript에서 보이지 않으므로,
규칙을 한 번만 말해두지 않으면 둘은 어긋납니다. 함수가 요구하지 않는 필드를 도구
스키마가 요구하면, 호출은 레코드에 닿기도 전에 거절됩니다.

함수 목록은 모든 마이그레이션이 적용된 데이터베이스에서 생성됩니다. 누군가
적어둔 것이 아니라 실제로 거기 있는 것을 말합니다.

## 표 읽는 법 [#reading-the-tables]

EXECUTE 권한은 함수 호출을 허용합니다. 함수가 건드리는 모든
테이블에 행 수준 보안이 그대로 적용되고, 대부분의 함수는 그 위에 스스로
게이트를 겁니다. `member_leave_days_set`은 누가 불렀든
`public.is_company_admin()`이 성립하지 않으면 예외를 냅니다.

보안 모드는 `definer`와 `invoker`입니다. `invoker` 함수는 호출자로
실행되므로 행 수준 보안이 대신 답합니다. `definer` 함수는 소유자로 실행되어 그
정책들을 넘어 볼 수 있는데, 한 사람의 연차 잔여를 테이블 전체를 열지 않고
돌려주는 방법이 이것이고, 동시에 호출자와 그 함수가 닿을 수 있는 모든 것 사이에
그 함수의 본문만 서 있다는 뜻이기도 합니다.

스키마의 정본은 `supabase/migrations`이고, 테이블 설명은
[테이블이 뜻하는 것](/ko/docs/record/schema)에 있습니다.

## 로컬에서 실행하기 [#running-locally]

로컬 스택은 Docker 없이 Supabase CLI의 네이티브 런타임으로 돕니다. `tools/with-local-plane`이 이를 시작하고,
한 번에 명령 하나를 위해 붙들고 있다가 15분간 놀면 멈춥니다.

```bash
tools/with-local-plane supabase db reset                      # 스키마와 픽스처
tools/with-local-plane supabase test db                       # pgTAP
cd web && ../tools/with-local-plane bun run dev               # 이 스택에 붙은 웹 앱
```

리셋만으로 로그인할 수 있는 회사가 생기며, `member1@example.com`과 `seed-password`를 씁니다. 픽스처는
`supabase/seed.dev.sql`에만 있으므로 리셋은 그 파일에 없는 것을 지웁니다. 스키마를 바꿀 때마다
`supabase test db`를 실행하세요. SQL 함수 본문은 호출 시점에 해석되므로, 함수를 만든 마이그레이션 안에서
이름을 바꾸면 조용히 깨지고 이를 알아채는 것은 pgTAP뿐입니다. 테이블을 만드는 마이그레이션은 권한도
부여해야 합니다. 새 데이터베이스에서 `anon`, `authenticated`, `service_role`은 권한 없이 시작하기 때문입니다.
