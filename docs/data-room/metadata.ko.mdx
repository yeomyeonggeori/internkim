---
title: 메타데이터
description: 모든 문서가 지니는 라벨, 바이너리에 필요한 사이드카, 김인턴이 대신 채우는 것.
---

데이터룸의 모든 문서는 라벨을 지닙니다. 파일 맨 위에 놓인 짧은 항목 묶음이고,
프런트매터라 부릅니다. 텍스트 문서는 라벨을 자기 안에 지닙니다. PDF,
스프레드시트, 이미지, 영상은 사이드카에 지닙니다. 바이너리 이름 뒤에 `.md`를
붙인 마크다운 파일이 옆에 놓이는 것으로, PDF 옆의
`2026-03-15-audit-report-fy2025.pdf.md`가 그것입니다. 항목은 어느 쪽이든
같습니다.

사람이 쓰는 것은 라벨뿐입니다. 데이터룸이 보여 주는 나머지 전부, 인덱스, 도메인별
목록, 검색 결과는 라벨에서 생성되고 라벨과 대조됩니다.

```yaml
---
id: fin-2025-audit-report
title: 2025 회계연도 감사보고서
kind: report
domain: finance
date: 2026-03-15
period: 2025
status: current
supersedes: fin-2024-audit-report
source: 삼일회계법인
language: ko
summary: 감사 적정 의견, 매출 42억, 영업손실 3억.
tags: [audit, k-ifrs]
sha256: ab12…
---
```

| 항목 | 담는 것 |
|---|---|
| `id` | 옮겨도 변하지 않는 안정된 이름; 문서를 가리킬 때는 언제나 이것을 쓰고 경로는 쓰지 않음 |
| `title` | 문서 자체의 제목, 어느 언어든 |
| `kind` | `contract`, `policy`, `report`, `deck`, `dataset`, `image`, `video` 중 하나 |
| `domain` | 보관된 도메인, 파일이 놓인 자리와 일치해야 함 |
| `date` | 문서가 말하는 시점의 날짜 |
| `period` | 다루는 기간, 있을 때만: 회계연도, 분기 |
| `status` | `current`, `superseded`, `draft` 중 하나 |
| `supersedes` | 이 문서가 대체하는 버전의 `id` |
| `source` | 만든 곳: 회계법인, 거래처, 팀 |
| `language` | 문서의 언어 |
| `summary` | 200자 이내: 사실과 그 크기 |
| `tags` | 검색용 단어 몇 개 |
| `sha256` | 바이너리만: 원본의 해시, 파생 텍스트의 키 |
| `published` | `00-public` 사본만: 언제, 누가, 그리고 `from`에 공개의 출처가 된 `id` |

열람 권한 항목은 없습니다. 열람 권한은 도메인의 것이므로 문서의 열람 권한은
옮겨야 바뀌고, 같은 문서가 두 열람 권한에 동시에 있을 수 없습니다.

## 요약 한 줄 [#summary]

`summary`는 김인턴이 그 문서가 찾던 것인지 판단하려고 읽는 한 줄이고, 목록에
그대로 복사됩니다. 문서가 무엇을 말하는지를 숫자와 함께 담습니다. "감사 적정
의견, 매출 42억, 영업손실 3억"은 대부분의 질문에 그 자체로 답합니다. "2025
회계연도 감사보고서"는 아무 질문에도 답하지 못합니다. 제목이 이미 그렇게
말했기 때문입니다.

## 바이너리의 사이드카 [#sidecars]

김인턴은 텍스트를 읽습니다. 스캔한 계약서나 한 시간짜리 영상을 자기 문맥에
넣는 일은 없습니다. 그래서 바이너리는 사이드카 없이는 데이터룸에 존재하지
않고, 하나를 보관하면 둘이 생깁니다. 사이드카는 라벨을 담고, 긴 문서라면
거기서 파생된 부분들의 목록도 담습니다. 파생물은 원본 옆
`.derived/<sha256>/` 아래에 있습니다.

| 종류 | 사이드카에 | 옆에 파생되는 것 |
|---|---|---|
| 이미지 | 캡션, OCR 텍스트, 행사와 장소 | 썸네일 |
| 영상 | 요약, 전사문의 첫머리 | 전체 전사문을 여러 부분으로, 키프레임 시트 |
| PDF, DOCX | 요약, 파생된 부분의 목록 | 절 단위로 나눈 텍스트 |
| XLSX | 시트 목록, 시트마다 한 줄 | 시트마다 CSV 하나 |

해시가 파생 폴더의 키이므로, 원본을 바꾸면 파생물은 무효가 되고 다시
만들어집니다.

## 덮어쓰지 않고 대체하기 [#supersede]

문서는 제자리에서 고쳐지지 않습니다. 개정된 계약서, 정정된 재무제표, 규정의 새
판은 옛 문서의 `id`를 `supersedes`에 적은 새 문서로 추가됩니다. 옛 문서의
`status`는 `superseded`가 되고, 그 자리에 남거나 도메인의 `archive/`로
옮겨집니다. 작년에 옛 `id`로 걸어 둔 참조는 그때 참이었던 것을 여전히
가리키고, `supersedes`의 사슬이 문서의 내력입니다.

아무도 갖지 않은 `id`를 가리키는 `supersedes`는 검사가 보고하는 오류입니다.

## 김인턴이 채우는 것 [#generated]

구성원이 문서를 보관하면 라벨 작업은 김인턴이 합니다. 해시를 계산하고, 종류를
감지하고, 텍스트를 뽑고, `id`와 요약과 제안 도메인을 넣은 사이드카 초안을
씁니다. 구성원은 초안을 확인하거나 고치고, 열람 권한 2나 3의 도메인으로 갈
문서는 옮기기 전에 언제나 사람이 확인합니다. 구성원이 내는 것은 문서 자체와,
초안이 틀렸을 때의 제목, 날짜, 도메인입니다.
