역할은 분류 코드 배열인 `readableCategories`를 가집니다. `F`는 앞으로
추가되는 분류까지 재무 하위 전체를 포함하고, `FS`는 재무제표만 포함합니다.
여러 활성 권한은 합쳐지며 제외 규칙은 없습니다. 읽기 역할과 회사 관리·문서
편집 권한은 별개입니다. 역할에는 대분류와 중분류 코드를 모두 지정할 수
있습니다. 자료를 넣을 수 있는 분류와 권한을 부여할 수 있는 분류는 다릅니다.

| readableCategories | 접근 범위 |
|---|---|
| `["F"]` | 재무 전체와 현재·이후 추가되는 모든 하위 분류 |
| `["FS"]` | 재무제표만 |
| `["FS", "FP"]` | 재무제표와 급여 |

하위 분류가 없는 분류에는 자료를 직접 넣을 수 있습니다. 하위 분류가 있는
대분류는 자료를 묶어 보여주며, 권한 부여 대상으로 사용할 수 있습니다.

관리자는 구성원, 내부 circle, 외부 이메일 또는 공개 대상에 역할을 부여합니다.
외부인은 초대한 이메일을 인증하고 수락해야 합니다. 회사 구성원이나 circle,
호스트 파일시스템 계정으로 등록되지 않습니다. 만료·회수 시 새로운 조회를
차단합니다. 원본 다운로드는 `canDownload`가 필요하며 텍스트 미리보기는
읽기 권한을 따릅니다. 이미 받은 파일은 회수할 수 없고 발급된 파일 링크는
10분 안에 만료됩니다.

공개는 별도로 명시해서 설정하며 `X`는 공개되지 않습니다. 역할 수정은
모든 활성 수신자의 범위를 즉시 변경합니다. 중분류 추가는 기존 대분류
수신자의 범위를 확장합니다. 변경 전에 수신자를 확인하세요.
분류 코드와 부모 관계는 유지됩니다.

새 구성원은 일반 구성원 역할을 받으며 처음 생성된 관리자는 경영진 역할도
받습니다. 이후 회사 관리자 여부를 바꾸는 작업은 읽기 역할을 변경하지
않습니다. 역할 부여·회수는 별도로 관리합니다.

## 코드로 여는 공유 링크

활성 직원은 본인에게 직접 또는 circle을 통해 허용된 범위 안에서 역할을
선택해 링크를 만듭니다. 경영진을 포함한 모든 역할을 사용할 수 있으며,
`X`에도 동일한 역할·생성자 권한 규칙을 적용합니다. 기본 유효 기간은 3일이며
선택 가능한 기간은
[`dataRoomLinkLifetimeHours`](https://github.com/yeomyeonggeori/internkim/blob/main/web/src/lib/data-room/links.ts)에
정의되어 있습니다. DB에서 최대 7일을 제한합니다.

앱이 생성한 6자리 코드는 한 번만 표시하며, DB에는 솔트를 적용한 비밀번호
해시를 보관합니다. 수신자는 코드 입력과 기밀유지 안내 동의 후 계정 없이
열람합니다. 열람 세션은 최대 1시간이며 링크보다 오래 유지되지 않습니다.
같은 네트워크 주소에서 15분 동안 코드를 10회 입력하면 추가 시도를 잠시
차단합니다. 링크 전체에서도 같은 시간 동안 최대 100회만 시도할 수 있습니다.

매 조회 시 링크 상태, 역할과 생성자의 현재 권한을 검사합니다. 역할 범위를
늘려도 생성자의 권한을 넘을 수 없습니다. 생성자와 회사 관리자는 링크를
파기할 수 있습니다. 이미 열린 화면의 추가 조회도 차단하며 다음 세션 확인 때
표시된 자료를 지웁니다. 원본 다운로드 주소는 최대 1분 뒤 만료됩니다.
내려받은 파일은 회수할 수 없습니다.

설정 → 회사에서 직원의 직접 부여 역할을 한 번에 교체합니다. circle 권한은
추가로 적용됩니다. 기밀유지 동의의 안내 버전과 시각을 기록하며, 별도
비밀유지 계약은 회사에서 관리합니다.

다른 분류로 옮기면 열람 대상이 바뀝니다.
