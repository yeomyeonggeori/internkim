김인턴이 회사 안에서 쓰는 도구는 전부 회사 밖에서도 HTTP로 부를 수 있습니다.
주소는 회사 웹 앱을 서빙하는 바로 그 호스트입니다. 토큰은 사람에게 속하고, 모든
호출은 그 사람으로 실행됩니다. 그래서 토큰이 주인보다 많은 일을 할 수 있는
경우는 없습니다.

`/api/v1` 요청은 전부 한 프로세스, `admind`가 받습니다. 토큰을 인증하고 범위를
확인한 뒤 일을 넘깁니다 — 도구 호출은 unix 소켓 너머의 `capabilityd`로, 에이전트
메시지는 로컬 HTTP로 Blueclaw 런타임으로. `/api/v1` 아래에서 도구를 직접
실행하는 코드는 없습니다.

## 토큰 발급 [#getting-a-token]

토큰은 로그인한 직원 웹 세션에서 나옵니다. Admin 화면의 토큰 섹션을 쓰거나,
세션 쿠키로 직접 요청합니다.

```bash
curl -X POST https://<host>/api/v1/tokens \
  --cookie "$SESSION" \
  --header 'Content-Type: application/json' \
  --data '{"label":"리포팅 스크립트","scopes":["write"]}'
```

```json
{
  "token": "ik_...",
  "actor": {
    "personID": "...",
    "email": "sample@example.com",
    "displayName": "이샘플",
    "source": "public_api_token",
    "scopes": ["read", "write"]
  },
  "record": {
    "id": "tok_...",
    "label": "리포팅 스크립트",
    "email": "sample@example.com",
    "scopes": ["read", "write"],
    "createdAt": "2026-08-27T00:00:00Z"
  }
}
```

`token`은 이때 딱 한 번 돌아옵니다. 서버는 SHA-256 해시만을 admind 상태
디렉터리(기본값 `/root/.internkim/state/admin`)의 `api-tokens.json`에
보관합니다. 토큰의 주인은 로그인한 세션의 당사자이고, 남 앞으로 토큰을 발급하는
길은 없습니다.

## 인증 [#authentication]

나머지 모든 엔드포인트는 bearer 헤더로 토큰을 받습니다.

```bash
curl https://<host>/api/v1/tools \
  --header "Authorization: Bearer $INTERNKIM_TOKEN"
```

토큰 주인은 요청마다 다시 확인됩니다. 주인이 현직 직원이 아니게 되면 그 토큰의
모든 호출은 그 순간부터 `403`입니다. 따로 정리할 것이 없습니다.

## 범위 [#scopes]

`read`는 요청 여부와 상관없이 항상 붙습니다. 요청한 범위는 소문자로 정규화되고
중복이 제거되며, 모르는 이름은 조용히 버려집니다.

권한 판정은 범위 이름이 아니라 등급을 비교합니다. 토큰의 등급은 가진 범위 중
가장 높은 등급이고, 도구가 요구하는 등급은 그 도구의 `sideEffectClass`에서
나옵니다.

| 등급 | 범위 | 열리는 것 |
|---|---|---|
| 1 | `read` | `sideEffectClass`가 `read`인 도구 |
| 2 | `write`, `external_write`, `external_send`, `publish`, `connect`, `companion`, `agent.run` | 워크스페이스 쓰기, 외부 수정과 발송, 게시, 연결, 브라우저 조작, 그리고 [에이전트 엔드포인트](/ko/docs/api/agent) |
| 3 | `destructive`, `admin` | 삭제를 포함한 전부 |

알아 둘 결과가 셋 있습니다.

- 2등급 범위 하나면 2등급 도구 전부가 열립니다. `connect`만 받은 토큰도
  `message_send`를 부를 수 있습니다.
- `admin`은 `destructive`보다 더 주는 것이 없습니다.
- 게이트웨이가 모르는 `sideEffectClass`를 가진 도구는 3등급을 요구합니다.
  모르는 것은 닫히는 쪽으로 처리됩니다.

## 오류 [#errors]

성공 본문은 JSON이고, 오류 본문은 평문입니다.

| 상태 | 본문 | 언제 |
|---|---|---|
| `400` | 디코드 오류, `message is required`, `conversationID is required` | 본문이 올바른 JSON이 아니거나 필수 필드가 빠졌을 때 |
| `401` | `bearer token required` | `Authorization: Bearer` 헤더가 없을 때 |
| `401` | `invalid bearer token` | 토큰이 모르는 것이거나 폐기됐을 때 |
| `403` | `staff web session required` | 로그인한 직원 세션 없이 `POST /api/v1/tokens`를 부를 때 |
| `403` | `token owner is not active staff` | 주인이 퇴사했거나 비활성화됐을 때 |
| `403` | `tool is not available for this token` | 토큰 등급이 도구가 요구하는 등급에 못 미칠 때 |
| `403` | `write scope required` | 1등급 토큰으로 에이전트 엔드포인트를 부를 때 |
| `404` | | 모르는 경로, 모르는 도구, 또는 토큰이 볼 수 없는 도구 |
| `500` | | 토큰 레코드를 저장하지 못했을 때 |
| `502` | | `capabilityd`나 에이전트 런타임이 실패했을 때. 본문에 원인이 담겨 옵니다 |

## 토큰 폐기 [#revoking-a-token]

조회는 `revokedAt`이 찍힌 레코드를 건너뛰므로, 폐기는 다음 요청부터 바로
적용됩니다. 이 값을 찍는 엔드포인트는 아직 없습니다. 지금 토큰을 폐기하려면
`api-tokens.json`에서 그 레코드에 `revokedAt`을 적고 저장합니다.

## 서빙되는 레퍼런스 [#the-served-reference]

같은 호스트의 `/api-docs`가 한국어와 영어 인터랙티브 레퍼런스를
`/openapi/<language>.json`의 OpenAPI 문서로부터 렌더링해 서빙합니다. 그 문서의
기본 도구 26개는 에이전트가 실제로 쓰는 카탈로그에서 그대로 읽어 옵니다.

## 구현 위치 [#where-it-is-implemented]

| 관심사 | 위치 |
|---|---|

| 토큰 발급, `ik_` 포맷, SHA-256 해싱, 저장 | 같은 파일의 `issuePublicAPIToken`, `publicAPITokenHash`; 저장 경로는 `publicAPITokenStorePath` |
| 범위 정규화와 등급 | `normalizePublicAPITokenScopes`, `publicAPIScopeRank`, `publicToolScopeForDescriptor`, `publicToolAllowedForActor` |
| `capabilityd`로의 도구 호출 전달 | `invokeCapabilityTool`, `CapabilitySocketPath`가 가리키는 unix 소켓 |
| 에이전트 엔드포인트 | `internal/admind/agent_drive.go`, `blueclawJSONRequest`로 Blueclaw에 전달 |

| 도구 카탈로그 | `pkg/capabilityprotocol/generated/capability-tools.json` |
