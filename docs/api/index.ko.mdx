김인턴이 회사 안에서 쓰는 도구는 전부 회사 밖에서도 HTTP로 부를 수 있습니다.
주소는 `https://api.intern.kim/v1` 하나이고, 우리가 호스팅하는 회사는 모두 이
주소를 씁니다. 어느 회사의 누구인지는 토큰이 말합니다. 김인턴을 직접 호스팅하는
회사는 자기 호스트의 `/api/v1`을 부르고, 그것도 같은 코드가 답하는 같은 API입니다.
토큰은 사람에게 속하고, 모든 호출은 그 사람으로 실행됩니다. 그래서 토큰이 주인보다
많은 일을 할 수 있는 경우는 없습니다.

요청을 받는 것은 웹 앱입니다. 부르는 사람을 확인한 뒤, 자기가 아는 것을 답합니다.
도구 카탈로그, 그 사람이 가진 토큰, 나중 호출을 위해 맡아 둔 파일, 그리고 기록
자체를 읽고 쓰는 도구가 그것입니다. 남는 것은 회사 컴퓨터가 있어야 합니다.
메신저, 워크스페이스, 브라우저가 그렇고, 그 호출만 그쪽으로 옮겨지고 답이
돌아옵니다.

## 토큰 발급 [#getting-a-token]

첫 토큰은 로그인한 상태에서, 설정의 개인 액세스 토큰 패널에서 만듭니다. 그때 한 번만
보입니다.

그다음부터는 토큰이 자기 후임을 만듭니다. 브라우저 없이 스크립트가 교체할 수 있습니다.

```bash
curl -X POST https://api.intern.kim/v1/token \
  --header "Authorization: Bearer $INTERNKIM_TOKEN" \
  --header 'Content-Type: application/json' \
  --data '{"name":"reporting script","permission":"write"}'
```

```json
{ "name": "reporting script", "permission": "write", "expiresAt": "2027-01-01T09:00:00.000Z", "token": "ik_..." }
```

`token`은 한 번만 답하고 기록에는 SHA-256 해시만 남습니다. 잃어버린 토큰은 되찾는 게
아니라 다시 만듭니다. `permission`을 생략하면 부른 토큰과 같은 등급이 되고, 자기보다
높은 등급은 만들 수 없습니다. `name`도 생략할 수 있고, 그러면 아직 안 쓰인 첫 번째
번호를 붙여 `pat-1`, `pat-2` 식으로 이름이 붙습니다.

토큰은 만든 지 90일 뒤에 만료됩니다. `expiresInDays`에 1부터 365까지의 정수를 주면
그 일수 뒤에 만료됩니다. 만료된 토큰으로 부르면 `401`로 답하고, 같은 이름으로 새로
만들면 갱신됩니다.

`GET /v1/tokens`는 구성원이 가진 토큰의 이름, 등급, 만료 시각, 마지막으로 쓰인 시각을
나열하고, 유일하게 복수입니다. 목록을 돌려주기 때문입니다. `POST /v1/token`이 하나를
만들고 `DELETE /v1/token?name=<name>`이 하나를 폐기합니다. 둘 다 언제나 토큰 하나만
건드립니다.

## 토큰 교체 [#rotating]

토큰은 자기 자신을 폐기할 수 없습니다. 그 제약이 교체를 안전하게 만듭니다. 새 토큰이
답하는 걸 확인한 뒤에야 옛 토큰이 사라집니다.

1. 옛 토큰으로 `POST /v1/token`을 불러 새 이름을 짓습니다.
2. 새 토큰으로 아무거나 불러서 답하는지 봅니다.
3. 새 토큰으로 `DELETE /v1/token?name=<옛 이름>`.

어느 쪽이든 제시한 토큰의 이름을 대면 `409`로 거부합니다.

## 인증 [#authentication]

나머지 모든 엔드포인트는 bearer 헤더로 토큰을 받습니다.

```bash
curl https://api.intern.kim/v1/tools \
  --header "Authorization: Bearer $INTERNKIM_TOKEN"
```

토큰 주인은 요청마다 다시 확인됩니다. 주인이 현직 직원이 아니게 되면 그 토큰의
모든 호출은 그 순간부터 `403`입니다. 따로 정리할 것이 없습니다.

로그인한 웹 세션도 같은 방식으로 통합니다. bearer 자리에 발급 키 대신 그 세션의
Supabase access token을 넣을 수 있습니다. 세션은 그 사람 자신이므로 전체
권한을 가지며, 웹 앱이 이 엔드포인트들을 부를 때 쓰는 것이 바로 이것입니다.
발급 키는 세션을 들고 있으면 안 되는 곳을 위한 것입니다. 스스로 권한 등급을
정하고, 로그아웃해도 살아남습니다.

## MCP 클라이언트 연결 [#mcp]

`https://api.intern.kim/v1/mcp`는 같은 카탈로그를 Streamable HTTP MCP 서버로
제공합니다. MCP authorization을 구현한 클라이언트는 이 주소만 있으면 됩니다.

```bash
claude mcp add --transport http internkim https://api.intern.kim/v1/mcp
claude mcp login internkim
```

토큰 없이 부르면 `401`과 함께
`WWW-Authenticate: Bearer resource_metadata="https://api.intern.kim/.well-known/oauth-protected-resource/v1/mcp"`를
답합니다. 그 문서가 플레인의 Supabase Auth를 authorization server로 지목합니다.
클라이언트는 거기에 자신을 등록하고, 사람이 로그인해 허용하도록
`intern.kim/oauth/consent`를 열고, 받은 토큰을 스스로 보관합니다. 이 토큰은 그
사람으로 움직이되, 동의 화면에서 고른 등급까지만 합니다. 읽기, 또는 읽기와
쓰기입니다. 등급을 고르지 않은 앱은 읽기만 하고, 어떤 앱도 회사를 관리하지
못합니다. 허용한 앱은 설정의 연결된 앱에 나오고, 연결을 끊으면 다음 호출부터
거부됩니다.

누구나 아무 이름으로 클라이언트를 등록할 수 있으므로, 동의 화면은 권한이 어디로
가는지도 보여줍니다. 내 컴퓨터의 클라이언트는 `localhost`나 앱 고유 주소로
돌아옵니다. 주소가 웹사이트이면 그 사이트가 권한을 받는다고 경고하니, 직접 연결을
시작했고 그 사이트를 알 때만 허용하세요.

### 아무것도 없는 데서 시작하기 [#starting-from-nothing]

그 창이 열리는 사람에게 아직 계정이 없어도 됩니다. 로그인 카드는 초대받은
주소를 등록하거나 회사를 새로 시작하도록 안내하고, 어느 쪽이든 기다리고 있는
authorization을 그대로 가지고 다니므로, 동의 화면으로 돌아와 거기서 클라이언트를
허용합니다.

앱 자신의 엔드포인트 둘이 OAuth access token을 받습니다. 클라이언트가 설정을
사람에게 되돌려주지 않고 끝까지 진행할 수 있는 이유입니다.

| 호출 | 하는 일 |
|---|---|
| `POST /api/company` | 로그인한 계정으로 회사를 만듭니다. 한 계정은 회사 하나를 만듭니다. |
| `POST /api/company/host-setup` | 회사 연결 파일을 답합니다. 회사 컴퓨터용 일회성 키가 들어 있습니다. |

`POST /api/company/host-setup`은 `ik_` 토큰을 거부합니다. 회사 컴퓨터를 연결하는
것은 활성 관리자 본인의 세션뿐이고, 발급 키는 세션이 아닙니다. 연결 파일을 어디에
쓰는지는 [퀵스타트](/ko/docs/quickstart)에 있으며, 설치는 그 컴퓨터에서
실행되므로 여기의 어떤 호출도 대신 하지 않습니다.

계정이 아직 어느 회사에도 속하지 않는 동안에는 모든 도구 호출이 `403`으로
그 점을 알려주고, 회사가 생기면 같은 클라이언트가 그대로 성공합니다.

[internkim 플러그인](https://github.com/yeomyeonggeori/internkim-plugin)은
`mcp.json`에 같은 서버를 선언하므로, 플러그인을 설치해도 같은 방식으로
연결됩니다. MCP authorization이 없는 클라이언트는 `ik_` 토큰을 bearer 헤더로
보냅니다.

## 권한 [#permissions]

토큰은 권한 하나를 가지고, 권한은 셋뿐입니다. 각 권한은 아래 것을 모두
포함하고, 도구가 무엇을 요구하는지는 이름이 아니라 `sideEffectClass`에서
나옵니다.

| 권한 | 열리는 것 |
|---|---|
| `read` | `sideEffectClass`가 `read`인 도구 |
| `write` | 그것과, 쓰기에 해당하는 모든 등급: 워크스페이스 쓰기, 외부 수정과 발송, 게시, 연결, 브라우저 조작, 그리고 [에이전트 엔드포인트](/ko/docs/api/agent) |
| `delete` | 삭제를 포함한 전부 |

쓰기에 해당하는 등급의 목록은
`web/src/lib/server/public-api/catalog.ts`에 있고, 거기 없는
`sideEffectClass`를 가진 도구는 `delete`를 요구합니다. 도구를 나열하는 앱에서
한 번, 도구를 실행하는 장비에서 다시 한 번. 모르는 등급은 양쪽 모두에서 닫히는
쪽으로 처리됩니다.

## 오류 [#errors]

성공 본문은 JSON이고, 오류 본문은 평문입니다. 앱이 JSON으로 답하는 예외가
둘 있습니다. 카탈로그 자신의 `{"error":"not found"}`, 그리고
[힌트 거절](/docs/api/tools#choosing-a-target-with-a-hint)인데 후자는 다음 호출이
하나를 정확히 지목할 수 있도록 `errorCode`, `failureStage`, `retryable`,
`safeRetry`, `hint`, `candidates`를 싣습니다.

답하는 기계가 둘이고, 둘은 문구를 공유하지 않습니다. 앱이 스스로 해결하는
것은 앱이 답합니다.

| 상태 | 본문 | 언제 |
|---|---|---|
| `400` | 디코드 오류, `this call carried a body that is not a json object`, `input is the object the tool reads` | 본문이 올바른 JSON이 아니거나 `input`이 객체가 아닐 때 |
| `400` | `<필드>: <스키마가 말하는 것>`, 예를 들어 `input.title: Invalid input: expected string, received undefined` | `input`이 그 도구가 공표한 `inputSchema`를 만족하지 않을 때 |
| `401` | `sign in first` | `Authorization: Bearer` 헤더가 없거나, 토큰이 가리키는 계정이 없을 때 |
| `401` | `that key belongs to nobody` | `ik_` 토큰이 모르는 것이거나 폐기됐을 때 |
| `403` | `refused` | 로그인한 계정이 어느 회사의 멤버도 아닐 때 |
| `403` | `token owner is not active member` | `ik_` 토큰의 주인이 퇴사했거나 비활성화됐을 때 |
| `403` | `this token may only <permission>, and <tool> <permission>s` | 토큰 권한이 도구가 요구하는 것에 못 미칠 때 |
| `403` | `write permission required` | 읽기 전용 토큰으로 에이전트 엔드포인트를 부를 때 |
| `404` | `{"error":"not found"}` | 이 토큰이 볼 수 없는 도구를 `GET /v1/tools/<name>`으로 물을 때 |
| `409` | `a token cannot revoke itself...` | 인증에 쓴 그 토큰을 `DELETE /v1/token`으로 지우려 할 때 |
| `409` | `errorCode`, `hint`, `candidates`가 실린 힌트 거절 | 힌트가 여럿을 맞혔거나, 가까운 것만 있거나, 아무것도 못 맞혔을 때 |
| `500` | `the control plane is not configured` | 앱에 Supabase 설정이 없을 때 |
| `502` | `the gateway answered <status>, and no status a caller can use` | 게이트웨이가 부르는 쪽이 쓸 수 없는 것을 답했을 때 |
| `503` | `the company gateway is not configured` | 회사에 닿는 길을 아무도 모르는 채로 실행을 부를 때 |

회사로 실려 간 호출은 `admind`가 자기 문구로 답합니다.

| 상태 | 본문 | 언제 |
|---|---|---|
| `401` | `bearer token required`, `invalid bearer token` | 회사 컴퓨터가 그 호출을 알아보지 못했을 때 |
| `403` | `token owner is not active member` | 주인이 퇴사했거나 비활성화됐을 때 |
| `403` | `asserted requester is not active member` | 지목된 요청자가 멤버가 아닐 때 |
| `403` | `tool is not available for this token` | 모르는 도구이거나, 토큰 권한을 넘는 도구일 때 |
| `502` | 해석에 실패한 내용 | 디스크립터나 액터를 읽지 못했을 때 |

## 파일 맡기기 [#keeping-a-file]

`POST /v1/files`는 바이트 자체를 받습니다. 최대 25 MB이고, 파일의 콘텐츠 타입과
선택적인 `?filename=`을 함께 받습니다. 파일은 회사 저장소에 보관되고 워크스페이스에
놓이며, 답에는 나중 호출이 그 파일을 가리킬 경로가 담깁니다. 읽기 토큰은 여기서
거부됩니다. 바이트를 어딘가에 두는 것은 쓰기이기 때문입니다.

## 토큰 폐기 [#revoking-a-token]

`DELETE /v1/token?name=<이름>`은 그 이름의 토큰을 잊습니다. 그 토큰을 든 다음
호출부터 거부됩니다. 토큰은 자기 자신을 폐기하지 못합니다. 그 자리를 대신한 토큰으로
폐기하세요.

## 서빙되는 레퍼런스 [#the-served-reference]

`docs.intern.kim/api`가 한국어와 영어 인터랙티브 레퍼런스를
`docs.intern.kim/openapi/<language>.json`의 OpenAPI 문서로부터 렌더링해 서빙합니다.
어느 회사 호스트에서든 `/api-docs`와 `/openapi/<language>.json`은 그리로 넘겨집니다.
그 문서의 기본 도구는 에이전트가 실제로 쓰는 카탈로그에서 그대로 읽어 옵니다.

## 구현 위치 [#where-it-is-implemented]

API는 웹 앱의 일부입니다. 앱을 직접 호스팅하는 회사는 API도 함께 갖습니다.
`api.<zone>/v1`과 `<회사 호스트>/api/v1`은 같은 라우트입니다.

| 관심사 | 위치 |
|---|---|
| `/api/v1` 아래 전체 라우팅 | `web/src/routes/api/v1/`; `/v1/*`는 `web/src/hooks.ts`에서 이 경로로 다시 씌워집니다 |
| 세션 토큰이든 `ik_` 키든, 부르는 사람의 신원 | `web/src/lib/server/member-request.ts`의 `callingMember` |
| 토큰 발급, `ik_` 포맷, SHA-256 해싱, 저장 | `web/src/lib/server/control-plane.ts`의 `issuePersonalAccessToken`; 규칙은 `web/src/lib/server/public-api/tokens.ts` |
| 권한 등급과 등급이 닿는 도구 | `web/src/lib/server/public-api/catalog.ts`, 바탕은 `web/src/lib/public-api-permission.ts` |
| 회사 장비로 도구 호출 전달 | `web/src/lib/server/public-api/company-call.ts`, `workers/connection-gateway`를 지나 회사 릴레이로 |
| 회사 장비가 그 호출로 하는 일 | `internal/admind/public_tool_gateway.go`의 `handlePublicAPI`, 그다음 `capabilityd` 소켓의 `invokeCapabilityTool` |
| 에이전트 엔드포인트 | `internal/admind/agent_drive.go`, `blueclawJSONRequest`로 Blueclaw에 전달 |
| 와이어 타입 | `pkg/capabilityprotocol/protocol.go` |
| 도구 카탈로그 | `pkg/capabilityprotocol/generated/capability-tools.json` |
| 테스트로 적힌 계약 | `web/tests/integration/public-api-route.test.ts`, `internal/admind/public_tool_gateway_test.go` |
| MCP authorization: 리소스 메타데이터와 `401` 챌린지, 동의 화면 | `web/src/lib/server/public-api/protected-resource.ts`, `web/src/routes/oauth/consent/`, `supabase/config.toml`의 `[auth.oauth_server]` |
| OpenAPI 문서와 `/api-docs` 리다이렉트 | `docs/web/app/lib/openapi.ts`, `web/src/lib/server/api-reference-redirect.ts` |
