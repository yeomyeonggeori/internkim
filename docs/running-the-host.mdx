The company host runs on Debian 13, Ubuntu 22.04 or 24.04, Fedora, RHEL-compatible 10 (Rocky, AlmaLinux) or Arch Linux, on arm64 or amd64, or on macOS with
Homebrew. It
needs an outbound internet connection and must stay awake. The installer registers native
services with systemd on Linux or launchd on macOS. The host needs no public
address, inbound port, or Docker installation.

## Install

Download the connection file from the company setup page, then run:

```bash
curl -fsSL https://intern.kim/install.sh | sh -s -- host
sudo internkim install ~/Downloads/internkim-host.json
```

The first command installs the package through apt, dnf, pacman or Homebrew. The second
configures the company, asks for the OpenRouter API key, and registers the host
services. They start with the computer and recover after a service exits. When
installation finishes, open the printed company setup address and choose
Check connection.

## Upgrade

Run the first command again. On Linux it downloads the latest release from
GitHub, checks it against the release's checksums, and installs it over the
version you have; on macOS Homebrew upgrades the formula. The company and its
data stay in place. To follow release candidates before they become the latest
release, add `--channel testing`:

```bash
curl -fsSL https://intern.kim/install.sh | sh -s -- host --channel testing
```

## Check services

On Linux, systemd shows the host service state and logs:

```bash
systemctl list-units 'internkim*' 'blueclaw*' 'buzz*'
systemctl status internkim-relay
journalctl -u internkim-relay -n 50 --no-pager
```

On macOS, run `launchctl print system/kim.intern.<service>` to inspect a
service. Its logs are under `/var/log/internkim/`.

## Settings

The installer writes company connection details and generated credentials to
the protected host data directory. Most companies do not need to edit these
files. Optional operator settings go in
`/etc/internkim/company-host.env`. The generated [host settings
reference](https://github.com/yeomyeonggeori/internkim/blob/main/host/README.md)
lists the supported variables and their defaults. Keep API keys and connection
files out of the settings file.

## Local data

The computer holds the agent's conversation history, task history, memory,
workspace files, and messages waiting for delivery. These are separate from
company records in the hosted service. Review [What lives where](/what-lives-where)
before backing up or replacing the host.

## Answer size

The relay replies with `413` and the byte count when an answer exceeds its
transport limit. The default ceiling is 3,000,000 bytes; set
`ANSWER_BYTE_CEILING` to change it. A non-positive value prevents startup.
Profile-picture limits are derived from this ceiling because base64 encoding
increases their size.

## Network access

The host opens outbound connections and listens only on local interfaces. To
administer the computer, use a shell on the same network or a remote access
method your company controls.

Installing or upgrading the package also downloads the host's one Python
runtime from `github.com`, and the pinned libraries that read attached
documents from `pypi.org` and `files.pythonhosted.org`. If either is
unreachable, the install stops and names what it could not fetch. The skills
run on the same runtime, as `python3` in each person's commands, and fetch
their own libraries from PyPI the first time they run.
